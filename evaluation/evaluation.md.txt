# Retrieval Evaluation Framework

## Objective

The purpose of this framework is to evaluate whether modifications to the retrieval pipeline improve the quality and usefulness of retrieved clinical evidence.

Rather than relying on subjective observations, every retrieval improvement should be assessed against a consistent set of benchmark queries.

---

# Scope

This framework evaluates **retrieval quality only**.

It does **not** evaluate:

- LLM answer generation
- Hallucinations
- Prompt engineering
- Medical correctness of the language model

The focus is to determine whether the retrieval system returns the most relevant clinical evidence for a given information need.

---

# Retrieval Philosophy

The objective of retrieval is not simply to return semantically similar text.

It is to retrieve **self-contained clinical evidence** that satisfies the user's information need while preserving enough surrounding context for meaningful interpretation.

### Design Principles

- Optimize for user intent rather than keyword overlap.
- Retrieve complete clinical concepts instead of isolated fragments.
- Preserve sufficient context to minimize unnecessary follow-up searches.
- Maintain topical focus throughout the retrieved results.

**Guiding Principle**

> Every retrieved chunk should ideally answer the user's next obvious question.

---

# Evaluation Strategy

The retrieval system will be evaluated using a benchmark dataset of representative clinical questions.

Each query will be tested after significant retrieval changes, including:

- Chunking strategy
- Chunk size / overlap
- Embedding model
- Retrieval configuration
- Future retrieval enhancements

The objective is to compare retrieval quality across iterations using the same benchmark questions.

# Evaluation Dimensions

For each benchmark query, retrieval quality will be assessed based on the following questions:

### Relevance

Did the retrieved chunks address the intended clinical question?

---

### Intent Alignment

Did retrieval satisfy the user's information need rather than matching keywords alone?

---

### Topical Focus

Did the retrieved results remain focused on the requested clinical concept without drifting into unrelated sections?

---

### Context Completeness

Did the retrieved chunks contain sufficient surrounding information to be understood independently?

---

### Practical Usefulness

Would a clinician need to immediately perform another search to understand the retrieved evidence?

# Benchmark Dataset Schema

The benchmark dataset (`benchmark_queries.csv`) contains evaluation queries used to assess retrieval quality across different question types.

# Benchmark Dataset

Benchmark queries are maintained separately in:

```text
evaluation/benchmark_queries.csv
```

Separating the benchmark from this document keeps the evaluation framework stable while allowing benchmark queries to evolve independently.

### Why Concept-based Evaluation?

The objective is to evaluate retrieval quality, not answer generation.

A retrieval is considered successful if it returns evidence containing the concepts required to answer the question, even if the wording differs from the benchmark keywords.

For example:

Question:

> What are the diagnostic criteria for PCOS?

Expected Concepts:

- Rotterdam criteria
- Hyperandrogenism
- Ovulatory dysfunction
- Polycystic ovaries

The retrieved text does **not** need to match these words exactly but should contain the relevant clinical concepts.
